What is Node.js and how is it different from traditional web servers?
Node.js is a JavaScript runtime built on Chrome’s V8 engine that allows you to run JavaScript code outside of a web browser. It is designed for building scalable network applications.

Differences from traditional web servers (like Apache, Nginx):

Features NodeJS Traditional Web Server
Execution Uses non-blocking, event-driven I/O Uses thread-per-request blocking model
Language JavaScript Often C, PHP, Python
Concurrency Single-threaded, handles multiple requests via event loop Multi-threaded or process-based concurrency
Performance High for I/O-intensive tasks Better for CPU-intensive tasks

Why is Node.js single-threaded, and how does it handle concurrency?
  • Node.js uses a single main thread for executing JavaScript code to avoid context switching overhead.
  • Concurrency is achieved through non-blocking I/O and the event loop:
    • While the main thread executes JavaScript, I/O operations (like reading files, DB queries) are delegated to worker threads or the OS.
    • Once the operation completes, a callback/event is pushed to the event loop queue
  • This allows Node.js to handle thousands of concurrent connections without spawning multiple threads.
what is concurrency?
  • Concurrency is a concept in computing that refers to the ability of a system to handle multiple tasks or operations at the same time, logically overlapping, even if the tasks are not physically executing simultaneously.
  • Concurrency = multiple tasks making progress together
  • It does not necessarily mean simultaneous execution; tasks may take turns being executed, but appear to run at the same time from the user’s perspective

Example

Imagine a restaurant chef:

  • Synchronous (non-concurrent): Chef cooks one dish at a time. Only when dish 1 is done, he starts dish 2.
  • Asynchronous (concurrent): Chef starts boiling pasta (waits for water), then chops vegetables while waiting. Both tasks progress without blocking each other. 
const fs = require('fs');

fs.readFile('file1.txt', () => console.log('file1 done'));

// Output order:

Both file reads are concurrent, thanks to the event loop.
What are callbacks in Node.js? What problems do they cause?

A function passed as an argument to another function, executed after some operation completes (often async)

Problems with Callbacks:

  • Callback Hell: Nested callbacks lead to deeply indented, hard-to-read code.
  • Error Handling: Managing errors across multiple callback layers can be complex.
  • Inversion of Control: Callbacks give control to the callee, making it harder to reason about flow.

What are Streams in Node.js? Types of streams?
  • Streams are objects that read or write data in chunks, rather than all at once.
  • Useful for large files, network data, or video streaming.
  • Types of Streams:
    • Readable: Data can be read from the stream (e.g., fs.createReadStream())
    • Writable: Data can be written to the stream (e.g., fs.createWriteStream())
    • Duplex: Both readable and writable (e.g., net.Socket)
    • Transform: A type of duplex stream that can modify the data as it is read/written (e.g., zlib.createGzip())

What are Promises and async/await in Node.js?

A Promise represents a value that will be available now, later, or never. It has 3 states:

  • Pending
  • Fulfilled (resolved)
  • Rejected

Example:

const fetchData = new Promise((resolve, reject) => {
  setTimeout(() => resolve("Done"), 1000);
});

Using .then() & .catch():

fetchData
  .then(result => console.log(result)) // "Done" after 1 second
  .catch(error => console.error(error));

Async/Await:

Syntactic sugar over Promises, allows writing asynchronous code in a synchronous style.

async function getData() {
    try {
        const result = await fetchData;
        console.log(result); // "Done"
    } catch (error) {
        console.error(error);
    }
}
getData();
How do you handle errors in asynchronous code?

In Node.js, errors in asynchronous code can be handled using:

  • Callbacks: First argument is an error object (if any)
  • Promises: .catch() method to handle rejections
  • Async/Await: try/catch blocks to catch errors

Using callbacks:

fs.readFile('file.txt', (err, data) => {
  if (err) return console.error(err);
  console.log(data.toString());
});

Using Promises:

promiseFunction()
  .then(data => console.log(data))
  .catch(err => console.error(err));

Using async/await::

async function run() {
  try {
    const data = await promiseFunction();
    console.log(data);
  } catch (err) {
    console.error(err);
  }
}
What are process objects in Node.js?

The process object is a global object in Node.js that provides information and control over the current Node.js process. It allows you to interact with the environment in which your application is running.

Common Uses:

  • process.pid → Process ID
  • process.cwd() → Current working directory
  • process.env → Environment variables
  • process.argv → Command-line arguments
  • process.exit() → Exit process
  • process.memoryUsage() → Memory details
  • process.uptime() → How long the process has been running
Difference between spawn, exec, and fork in Node.js

spawn()

  • Used to launch a new process with a given command.
  • Returns a ChildProcess object.
  • Streams stdout and stderr (suitable for large outputs).

Example:

    const { spawn } = require('child_process');

const ls = spawn('ls', ['-l']); // list files in directory

ls.stdout.on('data', (data) => {
  console.log(`Output: ${data}`);
});

ls.stderr.on('data', (data) => {
  console.error(`Error: ${data}`);
});
ls.on('close', (code) => {
  console.log(`Process exited with code ${code}`);
});

exec()

  • Used to run a command in a shell and buffers the output.
  • Returns the output via a callback (suitable for small outputs).

Example:

const { exec } = require('child_process');

exec('ls -l', (err, stdout, stderr) => {
  if (err) {
    console.error(`Error: ${err}`);
    return;
  }
  console.log(`Output: ${stdout}`);
});

fork()

  • Specialized version of spawn() to create a new Node.js process.
  • Used for inter-process communication (IPC) between parent and child processes.
  • Returns a ChildProcess object with an additional communication channel.

Example:

// parent.js
const { fork } = require('child_process');

const child = fork('child.js');

child.send('Hello Child');

child.on('message', (msg) => {
  console.log('Message from child:', msg);
});

// child.js
process.on('message', (msg) => {
  console.log('From parent:', msg);
  process.send('Got your message!');
});
How does clustering work in Node.js?

Clustering in Node.js allows you to create multiple child processes (workers) that share the same server port, enabling better utilization of multi-core systems and improving performance for CPU-intensive tasks.

How it works:

  • The main process (master) spawns multiple worker processes using the cluster module.
  • Each worker runs its own instance of the Node.js event loop and can handle incoming requests independently.
  • The master process distributes incoming connections across the workers using a round-robin algorithm (or other strategies).
  • If a worker crashes, the master can automatically restart it to maintain availability.

Example:

const cluster = require('cluster');
const http = require('http');
const os = require('os');

if (cluster.isMaster) {
  os.cpus().forEach(() => cluster.fork());
} else {
  http.createServer((req, res) => {
    res.end('Handled by worker ' + process.pid);
  }).listen(3000);
}
How can you achieve multithreading in Node.js?

While Node.js is single-threaded by default, you can achieve multithreading using the following methods:

  • Worker Threads: Introduced in Node.js v10.5.0, the worker_threads module allows you to create multiple threads within a single Node.js process. Each worker thread runs in its own V8 instance and can communicate with the main thread via message passing.
  • Child Processes: The child_process module allows you to spawn separate Node.js processes that can run concurrently. Each child process has its own event loop and memory space, enabling true parallelism.
  • Clustering: As discussed earlier, clustering allows you to create multiple worker processes that share the same server port, effectively utilizing multiple CPU cores.
What is libuv and what is its role in Node.js?

libuv is a multi-platform C library that provides Node.js with its event-driven, non-blocking I/O model. It abstracts away the underlying operating system differences and provides a consistent API for asynchronous operations.

Role of libuv in Node.js:

  • Event Loop: libuv implements the event loop, which is the core of Node.js's asynchronous architecture. It manages the execution of callbacks and handles I/O operations.
  • Asynchronous I/O: libuv provides non-blocking I/O operations for file systems, networking, and other system resources, allowing Node.js to handle multiple operations concurrently without blocking the main thread.
  • Thread Pool: For operations that cannot be performed asynchronously (like DNS resolution or file system operations), libuv uses a thread pool to offload these tasks, ensuring that the main event loop remains responsive.
  • Cross-Platform Support: libuv abstracts platform-specific details, allowing Node.js to run on various operating systems (Windows, Linux, macOS) without changes to the application code.
How do you handle uncaught exceptions in Node.js?

Uncaught exceptions in Node.js can be handled using the following methods:

  • process.on('uncaughtException', (err) => { ... }): This event is emitted when an exception bubbles all the way back to the event loop. You can log the error and perform cleanup tasks, but it's generally recommended to exit the process after handling the exception, as the application may be in an inconsistent state.
  • process.on('unhandledRejection', (reason, promise) => { ... }): This event is emitted when a Promise is rejected and there is no .catch() handler. Similar to uncaughtException, you can log the error and perform cleanup tasks.

What is JWT and how is it implemented in Node.js?

JWT (JSON Web Token) is a compact, URL-safe means of representing claims to be transferred between two parties. It is commonly used for authentication and authorization in web applications.

Structure of JWT:

  • Header: Contains metadata about the token (type, algorithm).
  • Payload: Contains the claims (user data, expiration time).
  • Signature: Ensures the token's integrity and authenticity.

Implementation in Node.js:

  • Install a JWT library like jsonwebtoken using npm.
  • Create a token upon user login, embedding user information in the payload.
  • Send the token to the client, typically in the Authorization header.
  • On subsequent requests, verify the token on the server to authenticate the user.

Example:

const jwt = require('jsonwebtoken');
const secretKey = 'your_secret_key';

// Create a token
const token = jwt.sign({ userId: 123 }, secretKey, { expiresIn: '1h' });
// Verify a token
try {
    const decoded = jwt.verify(token, secretKey);
    console.log(decoded); // { userId: 123, iat: ..., exp: ... }
} catch (err) {
    console.error('Invalid token');
}
What is rate limiting and how would you implement it in Node.js?

Rate limiting is a technique used to control the number of requests a user can make to a server within a specified time frame. It helps prevent abuse, reduce server load, and improve overall application performance.

Implementation in Node.js:

  • Use middleware like express-rate-limit for Express applications.
  • Configure the middleware with options such as windowMs (time frame) and max (maximum requests allowed).
  • Apply the middleware to specific routes or globally to all routes.

Example:

const rateLimit = require('express-rate-limit');
const limiter = rateLimit({
  windowMs: 15 * 60 * 1000, // 15 minutes
  max: 100 // limit each IP to 100 requests per windowMs
});
app.use(limiter); // Apply to all requests
How do you secure a Node.js app from SQL Injection & XSS?

SQL Injection Prevention:

  • Use parameterized queries or prepared statements to separate SQL code from data.
  • Use ORM libraries (like Sequelize, TypeORM) that handle query building and escaping.
  • Validate and sanitize user inputs to ensure they conform to expected formats.
  • Limit database permissions for the application user to only necessary operations.

XSS Prevention:

  • Escape user-generated content before rendering it in the browser (e.g., using libraries like DOMPurify).
  • Use Content Security Policy (CSP) headers to restrict sources of executable scripts.
  • Validate and sanitize inputs on both client and server sides.
  • Avoid using eval() or similar functions that execute arbitrary code.
  • Use secure templating engines that automatically escape output (e.g., Handlebars, EJS).
How does garbage collection work in Node.js?

Garbage collection in Node.js is managed by the V8 JavaScript engine, which uses a combination of algorithms to automatically reclaim memory that is no longer in use by the application.

Key Concepts:

  • Mark-and-Sweep Algorithm: V8 periodically scans the memory to identify objects that are still reachable (in use) and those that are not. Unreachable objects are marked for garbage collection.
  • Generational Garbage Collection: V8 divides objects into two generations - young and old. Young generation objects are short-lived and collected more frequently, while old generation objects are long-lived and collected less often.
  • Incremental and Concurrent Collection: V8 performs garbage collection in small increments to minimize pause times, allowing the application to continue running while garbage collection occurs in the background.

Best Practices to Optimize Garbage Collection:

  • Avoid memory leaks by ensuring that references to unused objects are removed.
  • Use tools like Node.js's built-in --inspect flag or third-party libraries (e.g., heapdump, memwatch) to monitor memory usage and identify leaks.
  • Optimize data structures and algorithms to reduce memory consumption.
  • Avoid creating large numbers of short-lived objects in performance-critical code paths.
