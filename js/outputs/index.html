JavaScript Scenario Questions

console.log(typeof NaN);
Output & Explanation
"number"
In JavaScript, NaN (Not-a-Number) is still considered a numeric value. That’s why typeof NaN returns "number".
console.log([] + []);
Output & Explanation
"" (empty string)
  • Both arrays are converted to strings when using the + operator.
  • [].toString() becomes "", so [] + [] results in an empty string.
console.log([1, 2] + [3, 4])
Output & Explanation
"1,23,4"
  • In JS, the + operator is overloaded
  • If both operands are numbers, it does arithmetic addition
  • If either operand is a string, it does string concatenation
  • When arrays are involved, JavaScript tries to convert them into primitive values:
    •     [1, 2].toString() → "1,2"
    [3, 4].toString() → "3,4"
  • Since both are strings, the + operator concatenates them
    •     "1,2" + "3,4" becomes "1,23,4"
console.log(true + false)
Output & Explanation
1
  • In JavaScript, when you use the + operator with booleans, they are converted to numbers.
    •     true → 1
    false → 0
  • So the output is 1 + 0 = 1
console.log("5" - 2)
Output & Explanation
3
  • Unlike +, subtraction is not overloaded for string concatenation
  • it only works with numbers
  • So JavaScript tries to coerce both operands to numbers
    •     "5" → 5 (string to number conversion)
    2 → 2
  • So the output is 5 - 2 = 3

console.log([] == ![])
Output & Explanation
true
1. Evaluate the right-hand side (![])
[] is a truthy value.
![] → false.
So now the comparison is:
[] == false


2. Equality with == (loose equality)
When comparing an object ([]) with a boolean (false), JavaScript converts the boolean to a number.
false → 0
So it becomes:
[] == 0


3. Array to primitive conversion
[] when converted to a number → first .toString() is called.
[].toString() → "" (empty string).
Number("") → 0.
So [] also becomes 0.


4. Final comparison
0 == 0  // true

console.log([...'hello'])
Output & Explanation
["h", "e", "l", "l", "o"]
  • The spread operator (...) expands iterables (arrays, strings, sets, etc.) into individual elements
  • A string is iterable character by character
    •     "hello" → 'h', 'e', 'l', 'l', 'o'
  • When wrapped in an array literal
    •     [...'hello'] becomes ["h", "e", "l", "l", "o"]

(() => {
    let x, y;
    try {
        throw new Error();
    } catch (x) {
        (x = 1), (y = 2);
        console.log(x);
    }
    console.log(x);
    console.log(y);
})()
Output & Explanation 
1
undefined
2
  • The output is this as the code executes, try block throws error so control moves to catch block
  • In catch block, the x variable is taken as argument which brings the concept of shadow block scope (like global or function block scope) and new x variable is created for catch block which has no relation with outside variable
  • In catch block, x and y is assigned values. so x value is assigned to the local scope variable where as y remains independent of this shadow block scoped as it was not passed as argument to catch block and so the value of y is assigned to variable decalred at top
  • When the control moves out of catch block, the x variable remains undefined and y variable was assigned value
let a1 = a2 = [1, 2, 3];
a1.length = 2;
console.log(a1, a2);
Output & Explanation 
[1, 2] [1, 2]
  • As Right-to-left assignment, a2 = [1,2,3] creates an array and assigns it to a2
  • Then a1 = a2 assigns the same reference to a1
  • Now a1 and a2 both point to the same array in memory
  • Setting .length = 2 truncates the array in place
  • So [1,2,3] becomes [1,2]
